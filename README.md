# Bedgorm — Catm-Up! · Phase 1

เกมกระดานภาษาไทยสำหรับผู้เล่นหนึ่งคนและบอต 2–7 ตัว เล่นในเบราว์เซอร์

## เริ่มพัฒนาต่อ

ใช้ Node.js 24 สำหรับชุดทดสอบ คำสั่ง `node --test test/rules.test.mjs` รันได้โดยไม่ต้องติดตั้งแพ็กเกจ เปิด `dist/` ผ่าน static HTTP server เช่น `python3 -m http.server 8000 --directory dist` แล้วเข้า `http://localhost:8000/` เบราว์เซอร์โหลด ES modules ผ่าน HTTP ส่วนการเปิด index.html ด้วยการดับเบิลคลิกขึ้นกับข้อจำกัด file:// ของเบราว์เซอร์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `dist/engine.mjs` | ตั้งสนาม สุ่มแบบกำหนด Seed ได้ ตรวจ action เคลื่อนกองแมว และคิดคะแนน |
| `dist/bot.mjs` | สร้างข้อมูลที่บอตเห็นและเลือก action ง่าย ปกติ หรือยาก |
| `dist/session.mjs` | บันทึกการตั้งค่า สถานะเกม และ deadline แบบ versioned ใน localStorage |
| `dist/app.mjs` | หน้าคลังเกม ห้องแข่ง สนาม คู่มือ ผลคะแนน และตัวจัดการเวลา |
| `dist/effects.mjs` | เคลื่อนไหวตามผลกติกาและสร้างเสียงด้วย Web Audio |
| `dist/index.html`, `dist/style.css` | โครงหน้า ธีม ภาพการ์ตูน CSS และ responsive layout |
| `test/rules.test.mjs` | ทดสอบกติกา ข้อมูลบอต การกู้คืน และการจำลองทั้งเกม |

## Game state

- `track` เก็บหมายเลขช่องเป็นคีย์และกองแมวเรียงจากล่างขึ้นบน ตำแหน่งนอก 1–16 ใช้จัดอันดับเมื่อจบแบบข้ามเส้นชัย
- `turn`, `step`, `leg`, `draw`, `rolled` และ `stock` คุมลำดับการแข่งขันและทรัพยากรในรอบย่อย
- `players` เก็บเหรียญ ตั๋ว หุ้นส่วน และ ledger แยกเหตุผลของคะแนน ส่วน `overall` เก็บคำทายลับเป็นสองลำดับ
- `act(game, action)` คืนสถานะใหม่เมื่อ action ถูกกติกา คืนออบเจ็กต์เดิมถ้าไม่ผ่าน `legal(game)` ส่วน `lastMove` ใช้สร้างภาพการเคลื่อนที่หลังคำนวณกติกาแล้ว
- `seed` และ `rng` ช่วยจำลองผลการสุ่มของสนามซ้ำเมื่อใช้ action เดิม ความสุ่มในการเลือกของบอตแยกจาก RNG ของเกม `botView` ตัด RNG และคำทายของผู้เล่นอื่นออก
- `deadline` เก็บนอก Rules Engine เมื่อตากำหนดเวลาหมดระหว่างออกจากหน้าสนาม จะทำ Auto Action เมื่อกลับเข้าหน้าสนาม

## การตัดสินใจในต้นแบบ

ให้ผู้เล่นจริงเริ่มตาแรกเสมอ ตั้งเวลาเริ่มต้น 60 วินาที และให้คู่หูคัดลอกตั๋วบวกมูลค่าสูงสุดโดยอัตโนมัติ บอตทุกระดับเลือกสุ่มลูกเต๋าเมื่อไม่มีใครสุ่มติดต่อกันครบจำนวนที่นั่ง เพื่อให้การแข่งขันเดินหน้า บอตยากจำลอง 24 เส้นทางจากข้อมูลที่เปิดเผย และประเมินผลตอบแทนโดยประมาณ การจำลองใช้ไอเทมปัจจุบันในรอบย่อยแรกแล้วล้างตามกติกา

อ้างอิงกลไกจาก [Camel Up Second Edition rulebook](https://meepletron-storage.s3.us-east-2.amazonaws.com/resources/camel-up-second-edition-rulebook.pdf) ภาพการ์ตูนและข้อความสอนเล่นจัดทำสำหรับ Bedgorm ชื่อ Catm-Up! เป็นชื่อระหว่างพัฒนา

## ย้ายไป Codex และ Multiplayer

ย้ายโฟลเดอร์นี้เข้า Git ได้โดยตรง ให้โฮสต์ static เสิร์ฟ `dist/` หากใช้ Sites เดิมต้องรักษา project ID และ manifest ในต้นฉบับที่ Sites จัดเก็บ ZIP สำหรับส่งต่อไม่มีข้อมูลประจำไซต์หรือข้อมูลรับรอง

สำหรับเกมออนไลน์ ให้ย้าย Rules Engine ไปเซิร์ฟเวอร์และเพิ่ม room ID, seat ID, match ID, turn/version, action ID และ transaction สำหรับกัน action ซ้ำ ให้เซิร์ฟเวอร์คุมเวลา RNG และคำทายลับ ส่งเฉพาะข้อมูลที่แต่ละที่นั่งเห็นได้ เพิ่ม reconnect, bot takeover, คืนการควบคุม, และบันทึก action/snapshot เพื่อกู้คืน พัฒนา room membership และ auth ก่อนเปิด matchmaking ต่อยอดชุดทดสอบสำหรับ concurrent submissions, reconnect race, timeout และการซ่อนคำทายข้ามผู้เล่น

Phase 1 ใช้เบราว์เซอร์เครื่องเดียว ข้อมูลอยู่ใน localStorage แยกตาม origin และโปรไฟล์ การล้างข้อมูลเว็บทำให้เกมล่าสุดหาย การรันเกมเดียวกันพร้อมกันหลายแท็บใช้การบันทึกล่าสุดของเบราว์เซอร์ จึงควรใช้หนึ่งแท็บต่อเกม การปิดแท็บหยุดการประมวลผลบอตจนกว่าจะกลับมา

## Phase 2 Review

ต้องใช้ Node.js 24.2 ขึ้นไป และใช้ฐานข้อมูล SQLite ในเครื่องโดยตรง ไม่ต้องติดตั้ง dependency เพิ่ม

```sh
npm test
npm run dev
```

เปิด http://127.0.0.1:8080/ แล้วเลือก **เล่นออนไลน์กับเพื่อน** ตั้งห้องอย่างน้อย 3 ที่นั่ง ตัวอย่างสำหรับสองคนคือ 3 ที่นั่งและบอต 1 ตัว ให้ผู้เล่นที่สองเปิดลิงก์เชิญในแท็บใหม่หรือเบราว์เซอร์อีกโปรไฟล์ แล้วกด **พร้อมแล้ว** เจ้าของห้องกดเริ่มเกมได้เมื่อครบทุกที่นั่งและพร้อมทั้งหมด ใช้เบราว์เซอร์และ origin เดิมเพื่อเล่นต่อหลังรีเฟรช

ค่าปริยายคือ bind เฉพาะ 127.0.0.1 พอร์ต 8080 และฐานข้อมูล `bedgorm-online.sqlite` ใน working directory สามารถตั้ง `BEDGORM_HOST`, `PORT` และ `BEDGORM_DB` ได้ ใช้ HTTPS และ persistent volume ในสภาพแวดล้อมจริง ขั้นตอน QA และแนวทางย้ายอยู่ใน `Bedgorm_Phase2_Review.md`.

Sites Review ใช้ static manifest เดิมสำหรับ Visual Polish และ Single Player การเปิดโหมดออนไลน์ต้องเสิร์ฟเว็บผ่าน Node backend ดังกล่าว เว็บที่เผยแพร่ Phase 1 และข้อมูลในเบราว์เซอร์ยังใช้การตั้งค่าเดิม
